O que foi construído

Assistente de conhecimento com RAG: você pergunta em linguagem natural, o sistema recupera trechos dos documentos e o LLM responde só com esse contexto. Take-home completo (E1–E7): banco, pipeline Python, API Go, MCP, testes e Compose.

A ideia em três passos

01 — ingerir

O texto vira chunks + vetores

Documento entra pela API Go. O Python fatia, gera embeddings MiniLM (384 dims) e grava no Postgres.

02 — buscar

A pergunta vira um vetor

pgvector (HNSW + cosseno) devolve os trechos mais parecidos. Sem trechos → 404, o LLM não inventa.

03 — responder

Ollama só usa o contexto

Prompt grounded + fontes (answer + sources). HTTP e MCP passam pelo mesmo run_query().

MCP — o que é, na prática

Não é um segundo RAG

Claude Desktop sobe python -m rag.mcp por stdio (JSON-RPC no stdout). A tool query_knowledge_base importa run_query(). Uvicorn pode estar parado; Postgres e Ollama precisam estar no ar, e o corpus já ingerido.

Schema da tool (enunciado)

Input:  { "question": string }
Output: { "answer": string,
          "sources": [{ "document_id", "chunk", "score" }] }

No HTTP a fonte se chama content; o MCP mapeia para chunk. MiniLM só carrega na primeira chamada da tool (handshake rápido).

Marcos E1–E7

E1

Banco feito

Postgres 16 + pgvector. documents, chunks, embeddings vector(384), HNSW cosine, CASCADE.

E2

RAG Python feito

Chunk com overlap, MiniLM, repositório pgvector, POST /ingest e estrutura de /query.

E3

LLM grounded feito

Ollama, prompt “só use o contexto”, answer + sources. Corpus vazio → 404, sem alucinação.

E4

API Go feito

Fachada REST: health, documents, ingest, query, delete. Metadata no Postgres; RAG só por HTTP interno. Erros {error, message}.

E5

MCP feito

query_knowledge_base reutiliza run_query(). Config Claude Desktop em services/rag/README.md.

E6

Testes feito

Mocks no vector store, LLM e cliente RAG; um teste de integração com Postgres real (LLM stub).

E7

Stack + seed feito

Compose (db, ollama, rag, api, web), make ingest em data/sample/, docs/api.md.

Por que Go + Python

  • Go: HTTP público, validação, metadata.
  • Python: chunk, embed, busca, LLM — uma implementação.
  • Mesmo Postgres (ops simples + CASCADE), hop HTTP extra vs monolito.
  • MiniLM local: sem custo de embedding; ingest mais lento.
  • MCP no host (stdio), não sobe no Compose. Sem auth (escopo do desafio).
